# Wave 2b Report — Lazy Per-Slice Data Loading (Audit M2.1 + M2.2)

Date: 2026-06-12. Scope: `index.html`, `functions/api/chat.js`, `sw.js`, new
`scripts/split_games.py`, `scripts/split_boxscores.py`, new `games/` and
`boxscores/` directories. Sources `games_1/2/3.json` and `sr_boxscores.json`
were NOT modified and stay deployed for one release (deploy-transition safety).

## What changed

### 1. scripts/split_games.py (new)
Splits `games_1/2/3.json` (66.8MB total, last-wins merge mirroring the old
frontend `Object.assign` and chat.js `games_3-first` lookup — no duplicate keys
exist today, verified) into:
- `games/{espnId}.json` — 370 per-team files, normalized `{"games": [...], "slug": "..."}`.
  169 legacy bare-array entries wrapped; 165 missing slugs filled from `espn_to_sr.json`
  (5 ids — 157, 2563, 2566, 2631, 2656 — have no SR slug mapping; file written without slug).
- `games/index.json` — manifest `{espnId: gameCount}`, 4.1KB.

Validated: 567,738 games written == source total; all 365 `data.json` H ids have
a file; sample-file shape re-read; deterministic + atomic (`json_io.save_json_atomic`)
+ idempotent (re-run verified). Largest slice: `games/150.json` (Duke) at 320KB.

### 2. scripts/split_boxscores.py (new)
Splits `sr_boxscores.json` (18.5MB) into `boxscores/{year}.json` (41 files,
1985–2026) keyed by the ORIGINAL game keys (`"YYYY/slug-vs-slug"`), plus
`boxscores/index.json` (`{years: {year: count}, _metadata}`). Validated:
2,892 entries == source minus `_metadata`; every key re-resolvable through its
year file; atomic, deterministic, idempotent.

### 3. index.html — lazy game loading
New infrastructure (right after the data declarations, ~line 5826):
- `loadGamesIndex()` — fetches `games/index.json` (4KB) once at init.
  **Fallback:** if the manifest 404s (split not deployed), sets
  `GAMES_LEGACY_MODE` and loads the old `games_1/2/3.json` monolith — identical
  to pre-change behavior.
- `ensureTeamGames(espnId)` — memoized per-team fetch of `games/{id}.json`;
  in-flight dedup; negative answers come from the manifest (no fetch);
  transient failures retryable.
- `loadAllGames()` — full-corpus load used ONLY by the NET proxy fallback (see
  consumer table). Tries the monolith first (still deployed); once the monolith
  is removed it fans out per-team from the manifest.
- `hasGamesData(espnId)` — synchronous existence check answered from the manifest.

`initializeApp` no longer fetches games_1/2/3 — it awaits `loadGamesIndex()` only.

#### SR boxscores (M2.2)
- `loadSRBoxscoresYear(year)` — fetches `boxscores/{year}.json`, cached per year;
  uses `boxscores/index.json` to return `{}` without a fetch for years with no
  data. **Fallback:** if the index is missing (pre-split deploy), loads the old
  whole `sr_boxscores.json` once and slices it.
- Call site 1 (upset game detail, ~17190): key is `"${year}/..."` → fetches that year only.
- Call site 2 (pre-2002 H2H box scores, ~21540): fuzzy-matches by team name within
  the game year — SR keys use tournament year, so it now fetches the game year
  AND the following year when the game date is Oct–Dec (matches the old
  `expectedYear` logic exactly).
- `loadSRBoxscores()` (whole file) kept solely as the transition fallback.

### 4. functions/api/chat.js
`getTeamGames(ctx, espnId)` now: checks a per-team cache → loads
`/games/index.json` once (8KB in worker memory) → fetches `/games/{id}.json`
(KBs). Teams absent from the manifest return null with no further fetches.
Legacy 3-file path kept verbatim as fallback if the manifest or a slice is
missing. Worker memory for games drops from ~67MB to the handful of team slices
a conversation touches.

### 5. sw.js
`CACHE_NAME` bumped `hoopsipedia-v3` → `hoopsipedia-v4` so installed PWAs evict
the cached megafiles on next activation.

## Risks / operational notes
1. **Pipeline must re-split after data updates.** Scrapers and nightly sync
   still write `games_1/2/3.json` / `sr_boxscores.json` as source of truth
   (scrape_batch.py, scrape_all_remaining.sh, nightly flow). `scripts/split_games.py`
   and `scripts/split_boxscores.py` MUST run after those files change, or
   `games/` and `boxscores/` go stale while the monoliths advance. Recommend
   adding both to the nightly sync tail and the pre-push hook.
2. **One-release deprecation window.** games_1/2/3.json + sr_boxscores.json must
   stay deployed until this release is live everywhere; afterwards they can be
   deleted (loadAllGames then fans out per-team; chat.js legacy path returns null).
3. **~365 new files per deploy** in `games/` — well within Cloudflare Pages'
   20,000-file limit (current repo is far below it).
4. **OTD behavior change (intentional):** lazy mode sources data-driven facts
   from precompiled `on_this_day.json` (sig-scored by generate_on_this_day.py)
   instead of an ad-hoc scan of the full corpus. Headline phrasing differs
   slightly from the old generated sentences; hardcoded narrative facts still
   take precedence. Legacy mode keeps the original scan.
5. **NET proxy fallback is heavy by design:** if `data.json` ever ships without
   real NCAA NET data, `computeNetRankings` pulls the full corpus via
   `loadAllGames()` (documented in-code). Normal operation never hits it.
6. Offline analysis tools (`efficiency_engine.js`, `time_machine.js`,
   `generate_on_this_day.py`, audits) still read the monoliths directly — they
   run locally, unaffected, but will break if the monoliths are deleted without
   pointing them at `games/`.
