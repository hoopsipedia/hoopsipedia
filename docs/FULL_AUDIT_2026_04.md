# Hoopsipedia Full Audit - April 2026
## Use this document as a starting prompt for a Claude session dedicated to Hoopsipedia fixes

---

## CONTEXT FOR CLAUDE

This is a college basketball historical database at https://www.hoopsipedia.com/. The codebase is at /Users/joshdavis/Projects/hoopsipedia and on GitHub at https://github.com/hoopsipedia/hoopsipedia. It's hosted on Cloudflare Pages.

The site is a single-page application built as one monolithic index.html file (19,172 lines, 1.3MB) with all CSS, JS, and HTML inline. Data is stored in JSON files loaded client-side. There are Python scrapers that pull data from ESPN and Sports Reference.

An independent audit was conducted and found the issues below. Fix them in priority order.

---

## CRITICAL ISSUES (Fix First)

### 1. Two Incompatible ID Mapping Systems
- `slug_mapping.json` (582 entries) and `espn_to_sr.json` (373 entries) disagree on 121 team mappings
- Example: ESPN ID 150 maps to "pittsburgh" in slug_mapping.json but to "duke" in espn_to_sr.json
- `slug_mapping.json` was auto-generated by generate_slug_mapping.py which naively guesses SR slugs — 287 of its keys don't exist in data.json
- Running compile_history.py or compile_h2h.py with slug_mapping.json will silently corrupt seasons.json and h2h.json
- FIX: Delete slug_mapping.json entirely. Delete generate_slug_mapping.py. Update compile_history.py and compile_h2h.py to read from espn_to_sr.json instead

### 2. 73MB Client-Side Data Download on Every Page Load
Files loaded on every page visit:
- data.json: 0.71 MB
- seasons.json: 5.47 MB
- h2h.json: 1.44 MB
- games_1.json: 21.41 MB
- games_2.json: 21.48 MB
- games_3.json: 21.23 MB
- upset_history.json: 0.09 MB
- arena_photos.json: 0.04 MB
- team_history.json: 0.08 MB
- draft_history.json: 0.12 MB
- TOTAL: 72.06 MB + 1.33 MB index.html = 73MB

loadData() at line ~4682 fires all three games_N.json fetches simultaneously with Promise.all
FIX: Move to Cloudflare Workers API that serves per-team data on demand. At minimum, lazy-load games, seasons, and h2h only when user navigates to a page that needs them.

### 3. Catastrophic Empty Space Bug (Reported on Every Page)
Every page has thousands of pixels of blank space. Homepage is ~4,936px tall but actual content only ~1,200px. Same on Rankings, Bracket, and other pages. Likely a CSS container with fixed/min-height that's too large.
CONFIRMED VIA LIVE BROWSER AUDIT (April 6, 2026): The empty space bug is severe. After scrolling past the Final Four game cards, the ENTIRE rest of the page is blank — no footer, no "On This Day" section, no additional content renders at all. Even pressing End key lands on blank space. The page extends thousands of pixels with zero content. The nav bar appears to float in the middle of the viewport during scroll rather than sticking to the top. This is the #1 priority fix — nothing else matters if visitors hit a wall of blank beige after 2 scrolls.
FIX: Inspect main content containers and remove excessive height values. Content should dictate page height. Check for hidden sections that are allocated space but not rendering. Check if JavaScript that populates below-the-fold content (like "On This Day", Saturday's games, etc.) is failing silently.

## HIGH SEVERITY

### 4. 19,172-Line Monolithic HTML File
- ~4,400 lines CSS (inline style block)
- ~600 lines HTML
- ~14,700 lines JavaScript (inline script block)
- 222 functions
- Zero external JS/CSS files
- No minification, bundling, or tree-shaking
FIX: Split into styles.css, app.js (or modules), and index.html. Add a build step.

### 5. enrichWithLiveRecords() Makes 373 Individual ESPN API Calls Per Page Load
- Iterates all ~373 teams in batches of 10
- Makes individual ESPN API calls for each team
- 37+ sequential batches with 200ms delays = ~40 seconds of API hammering per visitor
- ESPN's API is undocumented/unofficial — this could get the domain blocked
FIX: Nightly sync already captures current records in data.json. Client-side enrichment should only run for teams playing today, not all 373.

### 6. Six Phantom Teams with 0-0 Records
- ESPN 2314: Knoxville Bulldogs
- ESPN 2332: Lewis Flyers
- ESPN 2907: Trinity International Trojans
- ESPN 2902: Fredonia State Blue Devils
- ESPN 2901: Staten Island Dolphins
- ESPN 2078: Bridgeport Purple Knights
These are non-D1 or defunct programs with no data.
FIX: Remove from data.json.

### 7. team_history.json Only Covers 68 of 373 Teams
82% of teams have empty program history sections.
FIX: Prioritize power conference teams, then expand. Or add a "Contribute" feature.

### 8. Hardcoded UConn Upset Takeover in init()
Lines 5831-5848: Unconditionally writes a UConn vs Duke upset takeover to localStorage. Every first visitor sees UConn-themed colors regardless of relevance. Tournament is over.
FIX: Remove the hardcoded takeover. Use the dynamic live upset detection system instead.

## MEDIUM SEVERITY

### 9. Old games.json (47MB) Still in Repo
Website uses games_1/2/3.json (split files) but games.json still exists. compile_schedules.py still writes to games.json, not the split files.
FIX: Delete games.json. Update compile_schedules.py to write to split files.

### 10. SeatGeek Integration is Dead Code
Lines 4467-4506: Placeholder API keys (PLACEHOLDER_CLIENT_ID, etc.). fetchTicketData always fails.
FIX: Remove entirely or implement with real credentials via server-side proxy.

### 11. SEO is Fundamentally Broken
- SPA with hash-based URLs (#team/duke-blue-devils)
- Google crawler sees empty HTML skeleton
- sitemap.xml uses query-param URLs with redirect IIFE that replaces them with hash URLs
- Cloudflare Pages Function injects OG tags (good for social sharing but not for search indexing)
FIX: Implement server-side rendering or pre-render static HTML for ~373 team pages.

### 12. nightly_sync.py Variable Scope Bug
Line 56-58: `item` references loop variable from line 49 after loop ends. If loop runs but no items match, `item` is the wrong value.

### 13. H2H Data Lookup Uses Wrong Mapping File
compile_h2h.py line 44 builds reverse_slug from slug_mapping.json (the broken one). H2H opponent attribution could be wrong.
FIX: Switch to espn_to_sr.json.

### 14. Duplicate ESPN ID Entries in slug_mapping.json

### 15. scraped_boxscores_raw.json is 13 Bytes

### 16. Multiple Scratch/Debug Files in Root Directory
_scrape_interim_28.json, _sr_audit.json, _scrape_one.py, _scrape_sequential.py, boxscore_scrape_log.txt, scrape_chain_log.txt, scrape_log_batch1.txt, scrape_auto.log, net_quads_correct.txt
FIX: Move to a /dev or /logs directory, or delete.

### 17. protected_records.json is Unused
Exists (4.7KB) but never loaded by JS client or Python scripts.

### 18. seasons.json.gz is Stale
Last modified March 16 while seasons.json was modified March 20. Not referenced by code.

## ARCHITECTURE RECOMMENDATIONS (Priority Order)

1. Kill the 73MB download — Cloudflare Workers API serving per-team data on demand
2. Unify mapping files — Delete slug_mapping.json, use espn_to_sr.json everywhere
3. Split index.html — Separate CSS, JS, HTML files
4. Fix the empty space CSS bug
5. Add server-side rendering for team pages (SEO)
6. Lazy-load game data — Only fetch when user views a team profile
7. Remove dead code — SeatGeek, hardcoded takeover, empty functions, debug files
8. Add CI/CD pipeline with data integrity validation before deployment
