# players.json — Player Index from the Box-Score Archive

Generated by `generate_players.py` from `sr_boxscores.json`. Deterministic
(byte-identical on re-run), written atomically via `json_io.save_json_atomic`.

## THESE ARE NOT CAREER STATS — READ THIS FIRST

**Every number in players.json is an "in our box-score archive" aggregate.**
A player's `games`, `totals`, `perGame` and `best` reflect only what we have
scraped. A four-year starter with one archived game shows one game.
**Any UI built on this data must label numbers as "in archived games",
never "career".**

### The archive is no longer tournament-shaped (changed 2026-07)

The June framing of this file — "~2,892 games, heavily NCAA-tournament
weighted" — **is obsolete and the old guidance to label the data
"tournament archive" is now wrong.** After the July Wayback/StatCrew
harvest the archive is **20,320 unique games** (359 duplicate entries were
collapsed on 2026-07-28), and:

| slice | share |
|---|---|
| Nov–Feb (regular season) | 72% |
| Mar–Apr (tournament window) | ~10% |
| undated | 19% |

Coverage is now **wildly uneven by program**, because it followed whichever
schools had deep archive sites. Median program coverage is **3.6%** of its
games, but the spread runs from Arkansas at 69.6% and Virginia at 61.2%
down to North Carolina at 9.3% and Duke at 13.7%.

### The consequence: raw totals rank harvest depth, not players

A leaderboard sorted by archive points is a *coverage* leaderboard. In the
current build the top entries are Charles Jenkins (Hofstra, 118 archived
games), Bryant Stith (Virginia, 105) and Antwan Carter (Longwood, 122),
while Christian Laettner — who topped the June list — does not appear at
all. Nothing changed about those players; only how deeply their schools
were scraped.

**Sort by `perGame` with a minimum-games floor instead.** That is
coverage-robust, and it produces an immediately recognisable list:

| 41.5 | 8 | Austin Carr | Notre Dame |
| 33.7 | 9 | Bill Bradley | Princeton |

Same sanity role the Laettner list played in June: if this list stops

## Schema

Top-level: JSON object keyed by `"<normalized-player-name>|<team-slug>"`,
e.g. `"david-robinson|navy"`, `"christian-laettner|duke"`.

- Normalized name: lowercased, apostrophes stripped, punctuation runs → `-`.
- Team slug: same slugification of the *canonical school name*. Long
  nickname forms are folded onto short school forms when both appear
  ("Texas A&M Aggies" → `texas-a&m`, "Navy Midshipmen" → `navy`) with a
  blocklist guard so distinct schools never merge ("Alabama State" is NOT
  folded onto "Alabama"). Note slugs may contain `&` (`texas-a&m`).
- Same name + same team slug ⇒ merged into one entry. Same name on
  different teams ⇒ separate entries. (Caveat: two different humans with
  the same name on the same program in different eras would merge — no
  jersey/era disambiguation exists in the source.)

Each value:

```json
{
  "name": "David Robinson",          // most frequent source spelling
  "teams": ["navy"],                 // canonical team slug(s); 1 per entry
  "games": 8,                        // archived games with a stat line
  "totals": {"pts":218,"reb":104,"ast":3,"stl":13,"blk":33},
  "perGame": {"pts":27.2,"reb":13.0,"ast":0.4,"stl":1.6,"blk":4.1}, // 1dp
  "statGames": {"pts":8,"reb":8,"ast":8,"stl":8,"blk":8},
  "best": {                          // highest-scoring archived game
    "pts": 50,
    "year": 1987,                    // season year from the entry key
    "date": null,                    // full date only when the source entry
                                     // carried a dated SR url (238 games)
    "opponent": "Michigan"           // canonical school name
  },
  "years": [1985, 1987]              // [min, max] season year in archive
}
```

Inclusion filter: a player needs **>= 2 archived games OR >= 15 points in a
single archived game** (drops garbage-time one-liners).

### null means "not recorded", never zero

`statGames` counts, per stat, how many archived games actually carried that
column — and it is the denominator `perGame` divides by. A stat no source
ever recorded for a player is `null` in both `totals` and `perGame`.

This exists because box scores did not always track every stat: assists,
steals and blocks are absent from most pre-1980 lines, and early-1950s
lines often print only points/FG/FT. 4,258 of 53,916 players have blocks
that were never recorded. Publishing those as `0` would state, as fact,
that a 1954 player recorded no blocks in a game nobody was counting blocks
in. **A UI must render null as "—", not 0**, and should prefer `perGame`
(already correctly denominated) over dividing `totals` by `games`.

#### Caveat: `statGames` counts the COLUMN, not the record-keeping

`statGames` counts archived games whose source carried that stat's field.
That is not the same as the stat having been kept at the time. Several
1950s-60s sources emit a zero-valued assists field for every player in an
era that did not record assists at all — Bob Burrow (Kentucky, 1955-56) has
`statGames.ast = 4` with a total of 0, which is a parser artifact, not four
assist-less games.

So a `perGame` value drawn from only part of a player's archived games is
weaker evidence than one drawn from all of them, and a 0 from a partial
sample may mean "not actually recorded". The players page handles this
without asserting anything it cannot support: a rate from a partial sample
is marked with an asterisk whose tooltip gives the exact denominator
("From the 4 of 16 archived games whose box score carried this column"), and
a partial-sample zero is additionally muted. Fixing it properly means
knowing which season each stat became official — do not hard-code those
years without a citation.

## Delivery: players.json is a master, players/ is what ships

`players.json` is a full-fidelity **build artifact**, exactly like
`games_1/2/3.json` and `sr_boxscores.json`. The browser never fetches it.
`scripts/split_players.py` produces:

- `players/index.json` (~152KB) — per-team manifest with **coverage
  denominators** (`archivedGames`, `logGames`, `coveragePct`, `espnId`,
  `nonD1`), plus two leaderboards: `pointsPerGame` (primary; floor of 8
  games) and `mostArchivedPoints` (named so it cannot be mistaken for a
  scoring record).
- `players/<team>.json` (median 12.7KB, max 166KB) — that program's full
  player records, no truncation.

Team slugs containing `&` ('texas-a&m') get a file-safe key recorded as
`file` in the index; collisions abort the build rather than merge.
Round-trip is asserted in `tests/test_engine_invariants.py`: the union of
slices must equal the master exactly, with no player in two slices.

The 5MB size cap is now **opt-in** (`--cap`). Applying it by default was
destroying real data once the archive passed ~20K games: the 2026-07-28
capped build dropped `perGame` and both `best.date`/`best.opponent` for
every player *and* discarded 21,942 players outright. Per-team slices make
the cap unnecessary.

### The parser was rejecting a third of a million real stat lines

The first 2026-07-28 build skipped 33,413 lines (8.2%). They were not junk:
`parse_player_line` dispatched on the presence of a `min`/`mp` column, so
any box score without a minutes field was discarded wholesale — which is
most pre-1980 sources. Fixing detection to be content-based (does the line
carry any stat column?) plus handling four rebound dialects
(`5`, `{"off":1,"def":4,"tot":5}`, `"1+5"`, `"0-0"`/`"1-1-2"`) and treating
`null`/`""`/`"-"` as not-recorded rather than fatal took skips to **174**
— all genuine non-players (DNP notes, `Team`/`TOTALS` rows).

The recovered players are exactly who you would expect from a pre-1980
blind spot, and they land where the record books say they should:

| ppg | G | player | note |
|---|---|---|---|
| 41.5 | 8 | Austin Carr (Notre Dame) | his 61 vs Ohio (1970) is still the NCAA tournament single-game record |
| 31.2 | 16 | Dan Issel (Kentucky) | |
| 30.1 | 42 | Gary Bradds (Ohio State) | 1964 national player of the year |

Guard against the obvious failure mode — a `TOTALS` row parsed as a player
would mint a 70-ppg phantom: **zero** players average above 45 ppg, and the
only 60-point games in the archive are Maravich's 64, Austin Carr's 61 and
Eddie House's 61. All three are real.

Both source schemas are handled: the canonical int-valued shape
(`min/pts/reb/ast/stl/blk/to`) and the older regex-scraper string-valued
shape (`mp/pts/trb/ast/stl/blk/tov`, from the `sr_boxscores_modern.json`
era — all 179 of that file's entries are already merged into
`sr_boxscores.json`, so only the one source file is read).

## Proposed page concept (later)

**"Tournament Legends" player pages + leaderboard.**
- `/players/` — sortable leaderboard fed from `players/index.json`.
  **Default the sort to per-game, not totals** (see the coverage warning
  above), keep the min-games toggle, and filter by team and era.
- `/players/<key>` — player card: archive totals, per-game line, best game
  ("50 pts vs Michigan, 1987 NCAA Tournament"), link back to each archived
  box score, and the team's season pages for the player's `years` span.
- Banner on every page: "Stats from N archived games, not career totals" —
  non-negotiable given the site's data-accuracy history. On a team page the
  index gives you the exact denominator, so say the true thing: "1,355 of
  Virginia's 2,215 games are archived (61%)". Do **not** call the archive
  tournament-heavy; that stopped being true in July 2026.
- Natural hook for the chat/AI feature: "who scored the most in our archive
  for Duke?" becomes answerable without fabrication.
- Growth path: as the 365K-game scraping project raises coverage, the same
  generator re-runs unchanged and the pages get denser; the `best`-game
  `date` field fills in as dated URLs become the norm.
